# ECPA cross-implementation open questions

Only decisions that affect independent implementations belong here.

| Question | Recommendation | Alternatives | Minimal experiment / decision evidence | Wrong-decision cost |
|---|---|---|---|---|
| Attestation data model and profiles | Freeze an encoding-independent data model first. Candidate mandatory profile: RFC 8785 JCS plus detached JWS. COSE remains a negotiable profile; in-toto/SLSA are provenance references only. No wire format is frozen yet. | COSE mandatory; provider-native envelopes; transport authentication only | Cross-language positive/negative vectors for canonicalization, signatures, freshness and replay before freezing a profile | Encoding lock-in, signature ambiguity, or evidence that cannot interoperate |
| Namespace and alias governance | Separate plugin security identity, capability type, and host-scoped resource instance. A provider emits an auditable `AliasResolutionReceipt` when mapping names. | One reverse-DNS namespace for all kinds; central numeric registry; repository-local names | Two independent providers resolve collisions and aliases across all three name kinds with identical receipts | Identity confused with type/instance, collisions, privilege confusion, expensive migration |
| Compositional trust roots | Define profiles with explicit proof boundaries for host-runtime attestor, node observer, orchestrator receipt and TPM/TEE. MVP recommendation is host plus node dual authority; hardware roots are optional. | Host-only authority; orchestrator-only authority; mandatory hardware attestation | Forgery, node compromise and orchestrator-staleness matrix showing which authority can prove each fact | False effectiveness, unverifiable private deployment, or unnecessary hardware dependency |
| Effective history versus current effectiveness | `EffectiveAtCommit` is an immutable historical fact. `CurrentlyEffective` is a derived predicate over lease, membership epoch and health evidence. | One mutable `Effective` flag; activation-only status; request-path sampling | Outage, expiry, restart and recovery trace showing historical commit remains true while current status decays and recovers | Erased audit history or stale live-effectiveness claims |
| Elastic target set | Freeze a `TargetSetSnapshot` plus membership epoch for each activation. Scale-out uses a separate Admission Extension Plan. Quorum is not the default; an unproven worker must receive no traffic. | Implicit live membership; default quorum; full reactivation for every scale event | Scale-out/in and worker-replacement traces proving no unobserved worker is exposed | Vacuous coverage, unsafe traffic, or permanent inability to scale |
| Exposure-gate authority | Standardize an abstract `ExposureGate`; concrete authority belongs to the host, router or deployment controller and must emit receipts. Kubernetes readiness is not evidence of ECPA `Effective`. | Manager-owned routing; provider-specific implicit gating; Kubernetes readiness as effectiveness | Crash matrix for host-, router- and controller-owned gates, including predecessor restoration and readiness/effectiveness divergence | Premature exposure, split routing, or authority escalation |
| Rollback outcome and external debt | Report `RESTORED_STRONG`, `RESTORED_BEHAVIORAL`, or `FAILED_SAFE`. External state uses saga compensation with explicit uncompensated debt. | Boolean success; byte equality only; best-effort operator declaration | Inject reversible and irreversible manager/external changes and independently classify equivalence and debt | False rollback success, hidden external damage, or needless outage |
| Logical journal portability | Freeze logical journal record, durability and recovery semantics only; do not freeze the SQLite schema. | Standard SQL schema; storage-specific conformance; event API without durability rules | Replay the same conformance trace on SQLite and a second independently implemented store | Storage lock-in or implementations that agree on records but recover differently |
| Current host/runtime scope (decided 2026-09-18) | The current paper and reference implementation target vLLM-HUST only. Establish external validity through multiple real plugin classes, process scopes, versions/topologies, and fault cells. Cross-runtime validation is deferred future work, not a current exit gate. | Reopen only after the vLLM-HUST evidence campaign and paper; historical corpus support for other runtimes remains factual corpus metadata | Verify the full mechanism and evaluation matrix deeply on vLLM-HUST; record any future cross-runtime study as a separately scoped project | Diluting the current study with shallow integrations, or overstating single-runtime evidence as cross-framework validation |
| Standardization and governance gate | Before any standard claim require two independent managers, two architecturally independent hosts/providers, an independent conformance runner, at least one external adopter, and public governance. Until then call ECPA a proposed contract. | Repository-owned candidate specification; two-organization review alone; immediate foundation governance | Public interoperability event satisfying every gate, with independent artifacts and issue governance | Premature standard claim, capture by one implementation, or stalled evolution |

The 112 review may add or retire entries, but a question is not closed without
the listed evidence or an explicit rejection record.
